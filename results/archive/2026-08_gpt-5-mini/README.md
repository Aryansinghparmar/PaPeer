# Archive: evaluation artifacts from before Oct 2026 (gpt-5-mini era)

These four files used to live at the repo root. They are kept unchanged (except
for a one-line correction banner on `eval_comparison.md`) as the historical
record. **None of them can be regenerated by the current code.** Current numbers
come only from `python scripts/reproduce_eval.py` (see `results/SUMMARY.md`).

## `eval_results.json` — the source of the "0.981 Faithfulness" figure

- **Data:** the 10 synthetic goldens in `goldens.json` (DeepEval `Synthesizer`
  output, LLM-written questions and expected outputs; not human-curated).
- **Runs:** one run. n = 10.
- **Code:** the original dense-only pipeline (no hybrid search, no reranker,
  no forced retrieval). That code is not in git.
- **Judge model:** not recorded. DeepEval version, date and cost were not recorded either.
- **LangSmith:** tracing was not configured when this run was made. It was added later,
  so this number was **not** measured with LangSmith telemetry.
- **Recomputed from the file:** mean Faithfulness = **0.9809** (rounds to 0.981).
  Per-case scores are 1, 1, 1, 0.938, 0.964, 0.944, 1, 1, 0.963, 1. All 10 are at or above 0.7, and the minimum is 0.9375.
  Case-level bootstrap 95% CI [0.965, 0.996] (audit §8). Other means: Contextual Precision 0.978, Contextual Recall 1.000,
  Contextual Relevancy 0.576 (5/10 pass), Answer Relevancy 0.991.
- **Format:** a bare list of `{input, actual_output, success, metrics[]}`. Results are in DeepEval
  completion order, not `goldens.json` order.

## `eval_baseline.json`, `eval_improved.json`, `eval_comparison.md` — curated retrieval A/B

- **Data:** the first 5 of the 7 cases in `goldens_curated.json` (`--limit 5`). n = 5, one run per config.
- **Models:** app `gpt-5-mini` (resolved to `gpt-5-mini-2025-08-07`) and judge `gpt-5-mini`.
  Embeddings were `text-embedding-3-small`. Threshold 0.7.
- `eval_baseline.json`: dense retrieval with no rerank (2026-08-15). `eval_improved.json`: hybrid + rerank,
  label `improved_fixed`, after the answer-gating change (2026-08-16). The earlier pre-fix hybrid run
  is kept here as `eval_improved_prefix.json`.
- Measured spend: baseline $0.425, pre-fix $0.326, post-fix $0.381.

### Corrections (provenance audit, Oct 2026)

1. **Category mislabelling.** The old `evaluate.py` zipped DeepEval results, which arrive in
   completion order, with categories, which are in input order. Every `category` field in these files and every
   per-case label in `eval_comparison.md` is therefore unreliable.
   - The pre-fix Faithfulness **0.667** case, with its canned "I wasn't able to find…" answer, was labelled
     `security`. Its actual input is **"What was Moltbot's total revenue in 2025?"**, the *unanswerable* case.
     The refusal that the answer-gating "fix" removed was the correct behaviour on that question.
     The story in `eval_comparison.md` Finding 1 and in the `rag_graph.py` comment ("the security case") is wrong.
   - In the post-fix per-case table, the `factual` and `multi-section` rows are swapped.
2. **The post-fix "unanswerable" case was judged against web text.** The forced-retrieve route could call
   Tavily `web_search`. That case's 9 retrieval contexts have no overlap with the PDF. Its answer cited an
   unrelated €114k figure and still scored Faithfulness 1.0. Tavily calls were not counted in cost.
3. **Small n.** n = 5 with a single run per config. Retrieval deltas between the configs are within
   run-to-run noise (Finding 2 of `eval_comparison.md` already says so).

The current `evaluate.py` fixes these problems:
- It maps results to cases by input text.
- It runs paper-only by default (`paper_only=True`; use `--allow-web` to opt out) and records tool calls by source.
- It records full provenance in every report.
